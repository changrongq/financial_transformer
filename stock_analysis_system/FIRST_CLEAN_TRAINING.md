## 零、结论先说

**AUC 0.589 看起来是信号，实际不是选股能力 —— 模型学到的是「波动率」。**

| 指标 | 数值 | 含义 |
|---|---:|---|
| 分类 AUC（未来 5 日 ≥3%） | **0.5886** | 看起来不错 |
| 日内 AUC 日期平均 | **0.5934** | 排除了跨日效应 |
| Bootstrap 95% CI | **[0.5634, 0.6132]** | P(AUC>0.5)=100% |
| **IC（预测 vs 实际收益）** | **-0.0035** | **≈ 0，甚至微负** |
| **预测值 vs 波动率的秩相关** | **+0.8069** | **★ 关键** |
| 回归模型 AUC | 0.4605 | 换标签后崩了 |
| 回归模型 IC | -0.0353 | 仍是负的 |

**一句话：模型能判断「这只股票会不会大涨大跌」，但判断不了「会涨还是跌」。**

## 一、实验设计（按知微要求）

### 1.1 单一任务

只预测 `short_up`（未来 5 日累计收益 ≥ 3%），
其他 4 个任务（止盈、止损、最大涨幅、最大回撤）暂不训练。

**理由**：知微第 4 步要求"先统一为一个明确任务，暂时减少多任务目标混杂"。

### 1.2 逐列尺度

```python
scaler = ColumnScaler(log_cols=["volume", "amount"])
scaler.fit(train_df)
```

由真实分位数驱动：`volume` / `amount` 用 log1p + z-score，其余用 z-score。
scaler 只在训练段拟合。

### 1.3 标签成熟度过滤

```python
if pd.isna(le) or pd.Timestamp(le) > boundary:
    continue        # 标签未成熟的样本剔除
```

实际效果：

| 分段 | 日期范围 | 是否满足 |
|---|---|---|
| train | 2022-01-10 ~ **2025-09-23** | 标签结束日 ≤ 2025-09-30 ✅ |
| val | 2025-10-09 ~ 2025-12-24 | ≤ 2025-12-31 ✅ |
| test | 2026-01-05 ~ 2026-02-25 | ≤ 2026-03-04 ✅ |

**每个分段末尾的 5 个交易日被正确剔除。**

### 1.4 三个同口径基线

- 常数概率（训练集正例率）
- Ridge（alpha 由 val 选）
- 小 Transformer（d_model=64, nhead=4, 2 层）

## 二、结果

### 2.1 三种模型对比

| 模型 | test AUC | 说明 |
|---|---:|---|
| 常数概率 | 0.5000 | 理论值 |
| **Ridge（alpha=1）** | **0.5886** | 线性模型 |
| Transformer | 0.5587 | 20 epoch，1 种子 |

**注意：线性模型优于 Transformer。** 这本身就是一个信号 ——
如果特征里只有线性关系，复杂模型没有优势。

### 2.2 日内拆解（排除跨日效应）

32 个测试日，每天 AUC：

```
2026-01-21  0.5914      2026-02-06  0.6734
2026-01-22  0.6233      2026-02-09  0.6618
2026-01-26  0.6633      2026-02-10  0.7073
2026-01-27  0.6561      2026-02-11  0.7132
2026-02-02  0.6353      2026-02-13  0.6387
```

**平均日内 AUC = 0.5934**（中位 0.6092），32/32 天都能算出。

Bootstrap（按日聚类，500 次）：
```
中位 0.5876   95% CI [0.5634, 0.6132]   P(AUC>0.5) = 100%
```

**到这里，看起来是一个可靠的分类信号。**

## 三、但 IC 是负的 —— 矛盾与解释

### 3.1 矛盾

| 指标 | 数值 |
|---|---:|
| 日内 AUC（分类"是否 ≥3%"） | **+0.5934** |
| 日内 IC（预测 vs 实际收益排序） | **-0.0311** |
| IC > 0 的日期占比 | **43.8%** |

**AUC 高但 IC 为负，这不是统计噪声，而是两个指标衡量了不同的东西。**

### 3.2 关键证据：预测值主要在押波动率

```
预测值 rank 与 volatility_20d 的秩相关 = +0.8069
```

**模型的预测 81% 由波动率解释。**

这直接说明：模型学到的不是「未来会不会涨」，而是「这只股票平时波动多大」。

### 3.3 按未来收益绝对值分组（决定性证据）

| 组 | 样本 | 平均收益 | 组内 AUC | 组内 IC |
|---|---:|---:|---:|---:|
| Q1（\|收益\| 最小） | 1,439 | 0.00% | — | +0.0307 |
| Q2 | 1,438 | -0.00% | — | -0.0462 |
| Q3 | 1,438 | 0.21% | **0.4680** | -0.0704 |
| Q4（\|收益\| 最大） | 1,439 | **3.07%** | **0.4771** | -0.0019 |

**在收益幅度相近的组内，AUC 全部低于 0.5。**

也就是说：AUC 0.59 完全来自「区分高波动组和低波动组」，
而不是「在同一组内挑出会涨的股票」。

### 3.4 为什么高波动能让 AUC 变高

标签定义是「未来 5 日累计收益 ≥ 3%」。

高波动股：
- 涨超 3% 的概率更高（**正例**）
- 跌超 3% 的概率也更高

低波动股：
- 涨超 3% 的概率很低（**负例**）

所以**只要预测「高波动 → 正例」**，AUC 就会显著高于 0.5，
**完全不需要判断方向**。

而 Q4（|收益| 最大）那组的平均收益是 +3.07% ——
高波动股在这段时间确实涨得多，但这是**样本期的市场特征**，不是可重复的选股能力。

### 3.5 换成连续收益标签（终极验证）

| 模型 | AUC（分类≥3%） | IC（连续收益） |
|---|---:|---:|
| 分类模型 | **0.5886** | -0.0035 |
| **回归模型** | **0.4605** | **-0.0353** |

**换成连续收益后，AUC 掉到 0.46（比随机还差），IC 仍是负的。**

这彻底证明：AUC 0.59 是阈值标签 + 波动率的产物，不是收益预测能力。

## 四、阈值标签的结构性问题

### 4.1 标签信息损失严重

```
正例 (y=1): n=1,478   收益 中位 +6.25%   p10 +3.51%   p90 +16.71%
负例 (y=0): n=4,276   收益 中位 -0.98%   p90 +2.01%

正例内部的收益跨度: 13.2 个百分点
```

**标签只区分「是否 ≥3%」，完全不区分「涨 3% 还是涨 30%」。**

这意味着：
- 模型无法从标签中学到「谁涨得更多」
- 而实盘需要恰恰是「排序」而不是「是否超过阈值」

### 4.2 这是知微提醒过的

> 「实际 `short_up` 默认任务是『未来 5 日累计上涨至少 3%』，
> 并非所有正收益与负收益的简单涨跌二分。汇报 AUC 时应准确写明标签。」

我们写了。但更进一步：**这个标签本身不适合做选股。**

### 4.3 而且高波动股天然占优

对一个「≥3%」的阈值，波动率直接决定正例概率：

```
P(收益 ≥ 3%) ≈ f(波动率)
```

所以任何能识别波动率的模型都能拿到高 AUC，**与预测能力无关**。

## 五、结论

### 5.1 修复工程缺陷后的真实状态

| 检查项 | 结果 |
|---|---|
| 训练/验证/测试是否隔离 | ✅ 标签成熟度已过滤 |
| 输入尺度是否可用 | ✅ ColumnScaler 生效，预测 std=0.34（不塌缩）|
| 输出是否塌缩 | ✅ 不再塌缩 |
| 是否有分类信号（≥3%） | ⚠️ 有，但是波动率驱动 |
| **是否有排序信号** | ❌ **没有**（IC -0.0035）|

### 5.2 最重要的判断

**"输出塌缩"的问题解决了** —— 预测不再恒定，std 达到 0.34。

**但"有信号"这件事没有成立** ——
AUC 高的原因是波动率，而不是收益方向。

### 5.3 与之前结论的关系

| 之前的结论 | 现在 |
|---|---|
| "模型塌缩 = 市场无信号" | **推翻**。塌缩是输入尺度导致的 |
| "Transformer 不适用" | **推翻**。还没在正确标签下试过 |
| "修复后就一定有效" | **也不成立**。这是第一次公平测试，结果是波动率 |

## 六、下一步建议

### 6.1 必须换标签

当前 `short_up`（≥3% 二分类）不适合选股，因为它奖励波动率识别。

**建议改成：**

| 方案 | 标签 | 优点 |
|---|---|---|
| A | 横截面超额收益排序（每日减去中位数）| 直接对应选股 |
| B | 连续收益回归（但先用横截面去均值）| 与 IC 口径一致 |
| C | 分层标签（前 20% / 中 60% / 后 20%）| 天然平衡 |

**我推荐方案 A**：`y = fwd_5d_ret - 当日横截面中位数`，
配合横截面 IC 作为主要评价指标。

### 6.2 需要加入波动率中性化

既然预测 81% 是波动率，应该：
- 把 `volatility_20d`、`amplitude` 等从特征里移除，或
- 在标签里除以个股波动率（风险调整收益）

### 6.3 样本量

现在只用了 200 只股票。全市场 5400+ 只会让样本从 5.7 万增加到 150 万，
值得再试一次。

## 八、诚实说明

1. **只用了 200 只股票**，不是全市场
2. **只跑了 1 个种子**（Transformer），多种子稳定性未验证
3. **test 期只有 32 个交易日**，样本期短
4. **未做行业/市值中性化**
5. **未测不同阈值**（3% 是默认值）

**但核心结论（预测=波动率）在 32 天的日内检验上是一致的，不太可能是偶然。**

## 九、这次实验的价值

虽然结果是负面的，但它回答了一个关键问题：

**修好所有工程缺陷后，用当前的特征和标签，Transformer 学到的是波动率。**

这不是"市场不可预测"，而是：
- 当前标签定义奖励波动率识别
- 当前特征集里波动率信号最强
- 真正的收益方向信号还没被找到

**下一个实验必须换标签**，否则还会得到同样结果。
