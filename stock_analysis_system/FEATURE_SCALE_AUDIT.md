**「输出几乎恒定」的直接原因已经找到：模型看不到绝大多数特征。**

## 三、float32 精度分析

### 3.1 关键概念

`np.spacing(x)` 是 float32 在 `x` 附近的**最小可表示增量**。

在 `amount = 1.56e9` 附近，`spacing = 128`。

**这意味着：**

- 任何绝对值小于 128 的信号，在与 `amount` 同处一个线性组合时，
  **在 float32 里根本无法表示**
- `return_5d = 0.73` 比 128 小 **175 倍**
- `return_1d = 0.2` 比 128 小 **640 倍**

### 3.2 逐列判定（`scale / spacing`）

`< 1` 表示该特征的变化量小于 float32 在最大量级的间隔 → **会被淹没**

## 四、真实数据扰动检验（决定性证据）

### 4.1 方法

用**原 `FinancialTransformer`**（input_dim=24、d_model=64、nhead=4、
num_layers=2、dim_feedforward=256、model_variant=flat、seed=17），
取真实数据的中位数行作为基准。

对**最小量级特征** `return_1d` 施加 **±10% IQR** 的扰动
（IQR = 0.0351，即 ±0.0035）。

### 4.2 结果

| 检查 | 输出最大差 |
|---|---:|
| **原始尺度** | **0.0000000000e+00** |
| **标准化后** | **7.1641951799e-03** |
| 改善倍数 | **7.16 × 10²⁷** |

**在真实数据上，把日收益率扰动 10% 个 IQR，原模型的输出完全不变化。**

这不是"难以保留"，是**在 float32 运算里彻底消失**。

### 4.3 与知微合成用例的对比

| | 知微合成 | 我们的真实数据 |
|---|---|---|
| 输入维度 | 32 | 24（8 列无数据） |
| 扰动对象 | `return_5d` ±0.1 | `return_1d` ±0.0035（10% IQR） |
| 原始尺度输出差 | 0.0（投影+LN 后） | **0.0（logit 层）** |
| 标准化后 | 0.0172 | **0.00716** |

**两条路径都得到精确的 0，互相印证。**

## 五、修复方案（由真实分位数驱动）

### 5.1 变换选择

按知微的要求「不要仅在末端补一个 LayerNorm」，
我们用**真实分位数**决定每列怎么变换：

| 条件 | 变换 | 适用列 |
|---|---|---|
| `scale > 1e3` 且全正 | **log1p 后 z-score** | `volume`, `amount` |
| 其余 | **z-score** | 其余 22 列 |

这比"统一 z-score"更合适：`amount` 的分布是强右偏，
log 变换后分布接近正态。

### 5.2 实现

```python
from transformer_fixes import ColumnScaler

scaler = ColumnScaler(log_cols=["volume", "amount"])
scaler.fit(train_df[feat_cols])          # 只在训练段拟合

X = scaler.transform(df[feat_cols])       # 应用到全量

# ★ 随 checkpoint 保存，推理时加载同一份
torch.save({"model": state, "scaler": scaler.to_dict()}, path)
scaler2 = ColumnScaler.from_dict(ckpt["scaler"])
```

**禁止在全量数据上重新拟合**（知微明确要求）。

### 5.3 验证

```
原始尺度扰动 return_1d → 输出差 0.0000000000e+00
标准化后同样扰动     → 输出差 7.1641951799e-03
```

## 六、顺带发现的第二个问题

> ⚠️ **2026-10-31 更正**：本节初版说「配置声明 32 个特征，实际只有 24 个有数据」，
> **这是错的**。原因是我手工构造 `df` 时没有 merge `stock_moneyflow`，
> 把"我的脚本没加载"误当成"数据不存在"。
>
> 走生产路径 `_load_trade_data_with_concepts` 后确认：
> **32 个特征全部有数据，0 个常数，0 个全 NaN。**
>
> 详见 [FEATURE_COLUMN_AUDIT.md](FEATURE_COLUMN_AUDIT.md)。

**真正的问题是时间覆盖缺口**：

| 表 | 起止 |
|---|---|
| `stock_data` | 2021-11-01 ~ 2026-10-29 |
| `stock_moneyflow` | **2025-01-02** ~ 2026-10-28 |

**样本分布：有资金流 37.9%，无资金流 62.1%（395.7 万行）。**

缺口期间 `build_layer_features` 第 106-109 行把 7 个资金流特征
`mask(..., 0.0)` 填成**常数 0**。

这意味着：

1. 训练集里 62% 的样本，这 7 列是零信息
2. 如果切分跨过 2025-01-02，训练时资金流恒为 0、验证时是真实值
   → **典型分布漂移**
3. 这可能部分解释了「测试比训练差」

**另外**：本节第 4.5 节的审计基于没有资金流的 df，
所以那 24 个列的分位数是可信的，但**缺失的 8 列结论作废**。

**更正后的有效结论**：32 列都有数据，其中
- `amount` / `volume` 主导量级（1e9 / 1e8）
- 其余 30 列中 22 列被淹没
- **资金流 7 列量级只有 1e-04 ~ 1e-06，比 amount 小 13~15 个数量级，
  即使数据齐全也必须靠 ColumnScaler 才能生效**

## 七、对结论的影响

### 7.1 必须更新的判断

| 原判断 | 现在 |
|---|---|
| "模型输出塌缩 → 市场无信号" | **撤回**。塌缩的直接原因是输入尺度 |

| "Transformer 不适用" | **撤回**。还没在正常输入下试过 |

### 7.2 仍然不能说的

**不能说"修好尺度就一定有效"。**

修复只是让模型**能看到**特征，不代表特征里有信息。
按知微的要求：修复后如果预定预算内仍无增量，
那时才能说"在明确的特征、任务、数据范围内没有增量"。
