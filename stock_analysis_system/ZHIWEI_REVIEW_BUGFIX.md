## 一、知微指出的三个问题（全部确认）

### 问题 1：卖出日漏记隔夜收益 ⭐ 最严重

**位置**：`timing_engine.py` 卖出分支

```python
elif target < pos:
    prev_eq *= (1.0 - slip - cost)   # ← 卖出日完全不吃收益
```

**为什么错**：前一日净值按**收盘**持仓估值，今天开盘才卖出。**昨收→今开的涨跌仍属于持有人。**

**正确的分段（知微给的公式）**：
```
gross_factor[t] = (1 + 昨日仓位 × 隔夜收益[t]) × (1 + 今日仓位 × 日内收益[t])
```

- 买入日：昨日空仓 → 不吃隔夜；今日持仓 → 吃日内
- 持有日：吃隔夜 + 吃日内 = 吃全天
- **卖出日：昨日持仓 → 吃隔夜；今日空仓 → 不吃日内**
- 空仓日：两段都不吃

**我做的合成验证**（修正前）：

| 场景 | 修正前净值 | 正确净值 |
|---|---|---|
| 卖出日低开 -10% | **1.000000** | 0.900000 |
| 卖出日高开 +10% | **1.000000** | 1.100000 |
| 持有日低开 -10%（对照） | 0.900000 | 0.900000 |

**卖出日无论涨跌，净值都一动不动 → 确认漏记。**

**为什么这个 bug 特别严重**：
我们自己的研究结论是"A 股隔夜平均为负（-14.9%/年）"。**如果卖出日的隔夜普遍为负，那当前回测系统性高估了收益——少算了亏损。**

### 问题 2：夏普用了净值绝对变化，不是收益率

**位置**：`stats()`

```python
r = np.diff(np.concatenate([[1.0], curve]))   # ← 这是净值变化，不是收益率
sharpe = r.mean() / r.std() * np.sqrt(244)
```

**正确做法**：`r[t] = curve[t] / curve[t-1] - 1`

**合成验证**（曲线 `[2, 1, 2]`）：

| | 数值 |
|---|---|
| 旧实现夏普 | **5.52268051** |
| 正确夏普 | **11.04536102** |
| 知微给的对照 | 5.52268051 / 11.04536102 ✅ **完全一致** |

**结论：所有历史夏普数字作废。**

### 问题 3：回撤的累计最高值没包含初始资本 1

**位置**：`stats()`

```python
dd = float((curve / np.maximum.accumulate(curve) - 1).min())
```

`curve` 从第 1 天开始，**没有把初始资本 1 纳入累计最高**。

**合成验证**（曲线 `[0.9, 0.81]`）：

| | 数值 |
|---|---|
| 旧实现回撤 | **-10%** |
| 正确回撤 | **-19%** |
| 知微给的对照 | -10% / -19% ✅ **完全一致** |

**结论：所有历史回撤数字被低估，作废。**

## 二、修正后的代码

### `run_strict_t1` 改为分段记账

```python
for i in range(1, n):
    target = 1.0 if bool(d.loc[i - 1, "sig"]) else 0.0
    prev_eq = eq[-1]
    prev_pos = pos                    # 昨日收盘仓位

    # 段 1：隔夜（昨收→今开），由【昨日仓位】参与
    overnight = o_t / c_prev - 1.0
    prev_eq *= (1.0 + prev_pos * overnight)

    # 段 2：日内（今开→今收），由【今日仓位】参与
    prev_eq *= (1.0 + target * intra)

    # 成本：仓位变动时收
    if target != prev_pos:
        prev_eq *= (1.0 - slip - cost)
        trades += 1

    eq.append(prev_eq)
    pos = target
```

full = np.concatenate([[1.0], curve])

## 四、知微其他几条也成立

### 高换手分析的未来信息（第 4 条）

**成立。** `test_high_turnover_intraday.py` 用**当天完整成交额**做流动性过滤，但当天成交额要收盘后才知道 → **这是前视信息**。

**修正方向**：改用 T-1 的成交额或滚动均值。（未做，标注为待修）

### 单位衔接（第 4 条）

**成立。** tushare `daily` 的 `vol` 单位是**手**（100 股），`close × vol` 得到的不是"元"，更不是"万元"。

`amount >= 5000` 这个阈值因此含义不明。

### `abs(gap) >= 9.5%` 当"买不进"（第 4 条）

**成立。** 它包含**向下跳空**，且没区分板块、日期、真实涨停价。**这个代理指标太粗糙。**

### 隔夜分析脚本未统一复权（第 5 条）

**成立。** 四个分析脚本仍用 `open / close.shift(1) - 1`：

- `analyze_overnight_intraday.py`
- `verify_ashare_overnight_mechanism.py`
- `analyze_global_overnight.py`
- `analyze_stock_overnight_cross_section.py`

**公司行动会被误记成隔夜收益。**

### "11 次独立实验"的说法（第 5 条）

**成立。** 6 个高相关 ETF + 5 个高相关指数，**不是 11 次独立实验**。

### 因果表述过强（第 6 条）

**成立。** 文档里写"T+1 本质上造成摩擦""验证了假说、直接后果"，**超出了证据强度**。

### 参数网格不是独立样本（第 6 条）

**成立。** 6 个相关 ETF × 20 组参数 ≠ 120 个独立样本。**54% 胜率不能当作统计显著性。**
