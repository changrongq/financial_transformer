## 二、Bug 1：滑点处理（钳星方向对，但真正的问题在别处）

### 钳星的推理

```python
entry_price = o * (1 + slip)
prev_eq *= c / entry_price       # = (c/o) / (1+slip)
```

他说：这是把滑点"除"进收益，而不是"减"掉。

**数学上完全正确：**
- 当前：`A = (c/o)/(1+s) - 1`
- 应该：`C = (c/o - 1) - s`
- 偏差 ≈ `(c/o) × s²/(1+s)`（二阶小量）

**实测偏差量级：**

| slip | A（除） | C（减） | 偏差 |
|---|---|---|---|
| 0.05% | +0.9495% | +0.9500% | -0.0005pp |
| 0.10% | +0.8991% | +0.9000% | -0.0009pp |
| 0.20% | +0.7984% | +0.8000% | -0.0016pp |

**滑点本身的处理偏差 < 0.002pp，可忽略。**

### 但顺藤摸瓜发现了真 bug：双重计算

在验证滑点时我发现，`slip=0` 时两个实现差了 **184pp**。追查后找到根因：

```python
# 持有期间（每天）：
elif target > 0:
    prev_eq *= (1.0 + d.loc[i, "ret"])    # ← 每天累乘收益

# 卖出当天：
elif target < pos:
    sell = o * (1 - slip)
    prev_eq *= (sell / entry_price)       # ← 又把整段涨幅算了一遍！
```

**持有期每天的收益已经累乘了，卖出时又用 `sell/entry_price` 把「买入价→卖出价」的整段涨幅再算一次 —— 每段持仓的涨幅被计算了两次。**

**这是一个严重的双重计算 bug。**

### 影响

| | 修正前 | 修正后 |
|---|---|---|
| 沪深300 择时 | **+300.2%** | **+115.7%** |
| 沪深300 优势 | +200.1pp | **+17.0pp** |
| 中证1000 择时 | +331.9% | **+111.7%** |

**虚高约 2.6 倍。**

### 修正

```python
if target > pos:      # 买入
    intra = float(d.loc[i, "intraday"])
    prev_eq *= (1.0 + intra - slip - cost)
elif target < pos:    # 卖出：只扣成本，不再重复算涨幅
    prev_eq *= (1.0 - slip - cost)
elif target > 0:      # 持有：吃全天
    prev_eq *= (1.0 + float(d.loc[i, "ret"]))
```

## 三、Bug 2：offset off-by-one（钳星说"需确认"，实际是错的）

### 现象

```
择时起点 (d[1]):          2012-05-31
买入持有起点 (df[off+1]):  2012-06-01   ← 晚一天
```

### 推导

```
df: 3504 行（index 0..3503）
add_signal 后 d: 3502 行（dropna 掉 2 行：df[0], df[1]）
run_strict_t1 的 curve: 3501 点（eq[1:]）
curve[0] ↔ d[1] ↔ df[3]

所以：
  offset = len(df) - len(curve) = 3504 - 3501 = 3
  buy_hold_curve 应该从 df[3] 买入
```

**旧实现有两个错：**
1. `buy_hold_curve` 从 `start_idx+1` 买入（晚一天）
2. `eq = [1.0]` 后 append 首日 → 返回数组首元素恒为 1.0，与 `run_strict_t1` 的 `curve`（`eq[1:]`）语义错位

### 修正

```python
def buy_hold_curve(df, start_idx=0, cost=0.0, slip=0.0):
    d = df.reset_index(drop=True)
    # 首日直接作为第 0 个元素（不再有冗余的 1.0 前缀）
    eq = [1.0 + float(d.loc[start_idx, "intraday"]) - slip - cost]
    for i in range(start_idx + 1, len(d)):
        eq.append(eq[-1] * (1.0 + float(d.loc[i, "ret"])))
    return np.array(eq)

def align_offset(df, curve_len):
    return max(0, len(df) - curve_len)   # 不再 -1
```

### 影响

| | 值 |
|---|---|
| 旧实现（买在 off+1） | +98.04% |
| 修正后（买在 off） | +98.65% |
| 差异 | **+0.60pp** |

**影响很小，但既然发现了就该修。**

当前结果：**全部对齐 PASS**。

## 五、结论

### 钳星这两处发现的真正价值

1. **第一处**：他的滑点分析在数学上对，但偏差是二阶小量（<0.002pp）。**然而正是这个验证动作，让我发现了真正的 184pp 双重计算 bug。**
2. **第二处**：他说"需确认"，实际是明确的 off-by-one。

**这两个加起来，把"6/6 跑赢、87.5% 参数胜、回撤改善"变成了"5/6 跑赢、54.2% 参数胜、回撤改善"。**

### 对钳星的建议怎么说

> **"这个滑点 bug，它影响的是'滑点 0.1%/0.2% 敏感性的结论'——恰恰是文档里用来证明'有安全边际'的关键测试。如果它错了，那个'安全边际'的说法就要打个问号。"**

**这句话完全说对了。** 0.05% 滑点就只剩 4/6，"安全边际"的说法应该改为"滑点必须控制在 0.05% 以内"。

| 提高长期收益 | ⚠️ **5/6，但上证50 跑输 69pp** |

**回撤改善是这套策略最稳的部分（6/6）。收益提升是次稳的（5/6）。参数稳健性最弱（54.2%）。**
