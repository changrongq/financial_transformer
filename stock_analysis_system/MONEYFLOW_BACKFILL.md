## 一、实施方案

### 1.1 接口选择

tushare `moneyflow` 支持 `trade_date` 参数，**一次返回当天全市场**：

```python
pro.moneyflow(trade_date="20240603")   # 返回 5091 行
```

只需 771 次调用（不是 5879 次按股票拉），大幅节省调用量。

### 1.2 字段映射

| tushare | 本地 | 说明 |
|---|---|---|
| `buy_sm_vol` / `buy_sm_amount` | 小单买入量 / 小单买入额 | |
| `sell_sm_*` | 小单卖出* | |
| `buy_md_*` / `sell_md_*` | 中单* | |
| `buy_lg_*` / `sell_lg_*` | 大单* | |
| `buy_elg_*` / `sell_elg_*` | 特大单* | |
| `net_mf_vol` / `net_mf_amount` | 净流入量 / 净流入额 | |

### 1.3 单位校准

用已有的 2025 年数据与 tushare 对比：

```
校准样本 5117 只
tushare/local 比值中位 = 1.000000
```

**单位完全一致，无需换算。**（均为万元）

### 1.4 性能优化过程

| 版本 | 方式 | 速度 |
|---|---|---|
| v1 | 串行 + `to_sql(append)` | 约 3 天/分钟（需 4 小时）|
| v2 | 串行 + `executemany` | 约 10 天/分钟 |
| **v3** | **6 线程拉取 + 串行 `executemany` 写入** | **23 天/分钟（34 分钟完成）** |

关键点：SQLite 单写，所以**只并发网络拉取**，写入保持串行。

## 三、过程中我犯的两个错误（记下来）

### 错误 1：验证公式写错了（第 1 次）

我一开始假设：

```
净流入额 = (大单买入 + 特大单买入) - (大单卖出 + 特大单卖出)
```

结果相对误差 100%，我以为是数据错了。

**实际上**：`净流入额` 不是"主力净额"，而是**全部四类单的主动买卖净额**。

### 错误 2：验证公式又写错了（第 2 次）

改成"四类买入 - 四类卖出"后，误差仍然是 100%。

查出真实关系：

```
四类买入总额 中位 7,068.26
四类卖出总额 中位 7,068.26
|买-卖| 中位 0.000000
```

**四类买入总额恒等于四类卖出总额**（都等于当日总成交额，
因为每笔成交同时计入一次买和一次卖）。

所以"买入-卖出"恒等于 0，**根本不可能是净流入额的定义**。

### 正确的口径

`tushare moneyflow` 有三个独立维度：

| 维度 | 字段 | 含义 |
|---|---|---|
| 1. 单笔金额分档 | `buy_sm/md/lg/elg_*` | 按单子大小分四档 |
| 2. 成交方向 | `net_mf_amount` | **主动买入 - 主动卖出**（内外盘）|
| 3. 与价格关系 | — | 由成交发生在买价/卖价决定 |

**"四类买入"和"net_mf"是两个正交的维度，不能互相推导。**

数据从始至终都是对的，是我的校验逻辑错了两次。

## 四、对特征工程的影响

### 4.1 资金流特征的定义是合理的

`features.py` 里：

```python
net_mf_amount_ratio = _safe_div(net_mf_amount, amount)
```

即「净主动买入 / 总成交额」，这是一个标准的资金流强度指标。

### 4.2 缺口消除后，分布漂移问题解决

补齐前：

| 分段 | 资金流特征 |
|---|---|
| 2021-11 ~ 2024-12（62%） | **恒等于 0**（被 mask）|
| 2025-01 ~ 2026-10（38%） | 真实波动值 |

补齐后：**全时段都是真实值**，不再有常数段与分布漂移。

### 4.3 但尺度问题依然存在

即使数据齐全，资金流特征的量级仍然极小：

```
net_mf_amount_ratio: 均值 -3.6e-05, std 6.7e-04
net_lg_amount_ratio: 均值 -1.7e-05, std 3.6e-04
```

**比 `amount`(1e9) 小 13~15 个数量级，在原始尺度下必然被淹没。**

**必须配合 `ColumnScaler`**（已在 `scripts/transformer_fixes.py` 实现）。
